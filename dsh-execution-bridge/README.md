# Local DSH Codex policy bridge

Version 0.1.0 targets Desktop 0.2.1-rc.2. Install this absolute directory through DSH's official Plugin Manager only after explicit human authorization. It is trusted in-process Host code. The `insert` bundle entry adds one component without replacing existing entries.

The existing authenticated owner Gateway exposes bounded codexBridge status/preflight/create/verify diagnostics; no new port or credential. New sessions use a dedicated empty preset, only three scoped file tools, and a monotonic guard denying all unsupported tools. Native child operations inherit the unchanged Codex state and requested bounds. The sandbox launcher must come from trusted Codex transport metadata.

No shell, PTC, terminal, subagents or plugin management tool is available. Tool writes cannot alter this linked package or DSH's configuration. The SDK uses the Host's configured model; optional per-new-session output caps do not change that default. New sessions are attached to the normal GUI workspace with a deterministic title before any prompt, so automatic title generation cannot create a separate model request. Human approvals are never answered by the bridge.

Use the paired Codex plugin to renew authority while observing. A 90-second lease cancels orphaned work. Metadata, policy and credentials are not persisted by this package; Host restart requires a new scoped session. Deactivation drains owned agents before removing protection and the preset.

The package is private and not published. Its runtime SDK peers are supplied by the installed DSH. Rebuild with the parent repository's npm run build. For a linked installation, use official Plugin Manager to disable/re-enable this bundle after a reviewed change; never reload it while its own task is active. Disable/remove only this bundle to roll back.
